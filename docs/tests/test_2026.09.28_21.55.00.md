## 2. Rate-Limiting (Login-Brute-Force)

11 Logins mit falscher E-Mail/Passwort von 127.0.0.1:

```
#1:401 #2:401 ... #10:401 #11:429 #12:429
```
**Ergebnis: ✓** Ab dem 11. Versuch korrekt 429 mit `"Too many attempts, please try again later."`.

**Nebeneffekt beobachtet**: Rate-Limit gilt IP-weit, d.h. echte Logins vom selben Host werden für 15 min geblockt. In Produktion ist das gewünscht (Brute-Force-Schutz); lokal in dieser Umgebung muss man darauf achten, keine Tests mit falschen Credentials durchzuführen, bevor man sich einloggen will.

## 4. Dawarich-Compat-Routen

**Bugfix entdeckt**: Dawarich-Router war auf `/api` gemountet, wurde aber vom echten
`assetsRouter` auf `/api/assets` überdeckt (früher in app.ts registriert). `toAsset()` wurde
nie aufgerufen → interne Felder (`path`, `hash`, `size`) wurden geleakt, Dawarich-Format
wurde nicht geliefert.

**Fix**: Router auf `/compat/api` verschoben. Dawarich-Konfiguration:
> Settings → Integrations → Photo services → URL: `http://<photos-host>:3001/compat`

**Tests nach Fix**:

```bash
# Server-Info
GET /compat/api/server-info
→ {"version":"1.117.0","versionUrl":"","licensed":false,"releaseVersion":"1.117.0"}   ✓

# Asset-Liste im Dawarich-Format
GET /compat/api/assets?pageSize=3
→ Array[3], Keys: id, deviceAssetId, deviceId, ownerId, fileCreatedAt, fileModifiedAt,
   localDateTime, updatedAt, originalPath, originalFileName, thumbhash, type,
   isFavorite, isArchived, isOffline, livePhotoVideoId, checksum, exifInfo   ✓
   (keine internen Felder wie path, hash, size)

# Zod-Validation: ungültiges Datum
GET /compat/api/assets?takenAfter=notADate
→ {"error":"Invalid datetime"}   ✓ (400 statt vorher 200 mit falschen Daten)

# Echte /api/assets weiterhin erreichbar
```
